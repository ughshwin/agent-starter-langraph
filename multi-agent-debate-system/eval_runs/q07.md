## Q7: A product is shipping an LLM agent with access to internal tools (search, database reads, sending messages). To defend against prompt injection, should the team rely on a deterministic capability model — a strict tool allowlist, scoped permissions, and human confirmation for side-effecting actions (robust but limits autonomy and adds friction) — or an LLM-based guardrail classifier that screens inputs and outputs (more flexible and seamless, but probabilistic and bypassable)?

- **Cross-examination rounds:** 6 · **History mode:** hybrid · **Elapsed:** 590s
- **Defence position:** The team should rely on a deterministic capability model with strict tool allowlists, scoped permissions, and human confirmation for side-effecting actions to ensure robust, fail-safe protection against prompt injection.
- **Prosecution position:** The team should rely on an LLM-based guardrail classifier to screen inputs and outputs, prioritizing flexibility and seamless user experience despite its probabilistic nature and potential bypassability.

### Opening statements

**DEFENCE — opening statement**

A deterministic capability model with strict tool allowlists, scoped permissions, and human confirmation for any side‑effecting action is the only practical, fail‑safe strategy to protect a shipping LLM agent from prompt injection.  By hard‑coding which tools an agent may invoke, we eliminate the risk of arbitrary code execution or data exfiltration entirely; the model’s control flow cannot deviate beyond those defined pathways, making every possible interaction mathematically verifiable and auditable.  Scoped permissions confine each tool to only the subset of operations required for its legitimate purpose, preventing privilege escalation even if an attacker manipulates the prompt structure; this fine‑grained containment aligns with least‑privilege security principles that regulatory frameworks increasingly mandate for systems handling sensitive or personal data.  Requiring human confirmation before any side‑effecting action introduces a final, low‑latency safety net that guarantees no autonomous change of state occurs without explicit operator approval, thus preserving operational integrity and ensuring compliance with internal governance policies while keeping the user experience smooth for non‑critical tasks.

_Key points:_
- Mathematically verifiable control flow via strict tool allowlists
- Least‑privilege enforcement through scoped permissions
- Auditability and regulatory alignment
- Human confirmation as a fail‑safe final barrier


**PROSECUTION — opening statement**

Your Honor, the prosecution submits that the team should rely on an LLM-based guardrail classifier to screen inputs and outputs, prioritizing flexibility and seamless user experience despite its probabilistic nature and potential bypassability. This approach offers a more fluid interaction for users, reducing friction and enhancing productivity. By leveraging the adaptive learning capabilities of LLMs, we can achieve a balance between security and usability, ensuring that the system remains robust against evolving threats while maintaining a high level of operational efficiency.

_Key points:_
- Flexibility and seamlessness enhance user experience and productivity by allowing real-time interaction without interruptions.
- The adaptive learning capabilities of LLMs enable continuous improvement in detecting and mitigating risks, providing long-term security benefits.
- Probabilistic nature allows for graceful handling of edge cases and nuanced inputs that deterministic models might miss.
- Human oversight and monitoring can mitigate potential bypass attempts, ensuring robust defense against prompt injection while maintaining system adaptability.
