### Opening statements

**DEFENCE — opening statement**

By shifting the checkout and order flow to an event‑driven choreography, we break the tight synchronous coupling that presently inflates tail latency during peak traffic. Each service emits discrete events and reacts independently, so a delay or failure in one component no longer blocks downstream steps; requests can continue processing while retries occur asynchronously behind the scenes. This decoupling eliminates cascading failures because each service’s health is isolated by the message broker’s queue guarantees, which absorb spikes and replay messages without propagating errors across the chain. Moreover, an event‑driven architecture allows horizontal scaling on a per‑service basis, letting us provision compute only for the services experiencing load surges, thereby reducing cost while improving throughput and conversion rates.

_Key points:_
- Decoupled components reduce tail latency by removing synchronous waits
- Failure isolation prevents cascading failures through message queue buffering
- Per‑service horizontal scaling optimizes resource utilization and cost
- Asynchronous processing improves overall system resilience during traffic spikes


**PROSECUTION — opening statement**

The court should rule in favor of retaining synchronous REST calls and implementing timeouts, retries, and a circuit breaker/orchestration layer. This approach leverages proven reliability patterns without introducing the complexity of event-driven systems. Synchronous REST calls offer straightforward integration and familiar operational practices for the team, which is crucial given their current expertise. The proposed enhancements will address tail latency and cascading failures effectively, as demonstrated by successful implementations in similar systems. Transitioning to an event-driven model would introduce unnecessary complexity, potential for misordered events, and require significant changes in infrastructure and team skills, which could lead to new challenges without clear benefits over the proposed solution.
