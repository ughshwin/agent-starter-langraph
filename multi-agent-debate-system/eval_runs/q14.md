### Opening statements

**DEFENCE — opening statement**

The Defence maintains that a GraphQL API is the superior choice for this project, primarily because it grants clients the ability to request exactly the data they require, thereby eliminating both over‑fetching and under‑fetching inherent in RESTful designs; this precision is indispensable when catering to a spectrum of frontends—from single‑page web apps to native mobile and IoT devices—each with distinct bandwidth constraints and UI demands. By exposing a single, strongly typed endpoint, GraphQL centralizes version control and schema evolution, allowing the backend team to iterate rapidly without fragmenting the API surface into proliferating endpoints that REST often engenders as client needs diverge; this streamlines maintenance and reduces technical debt over time. Modern GraphQL tooling—such as automatic query validation, caching directives, and fine‑grained authorization hooks—mitigates the perceived disadvantages of complex auth and attack surfaces, offering developers robust security controls without sacrificing performance or developer ergonomics. Finally, the intrinsic introspection capability of GraphQL furnishes an evolving, self‑documenting contract that empowers frontend teams to discover fields, types, and relationships on demand, fostering faster onboarding and reducing reliance on external documentation; this agility directly translates into quicker time‑to‑value for new feature releases across all user interfaces.

_Key points:_
- Flexible data fetching eliminates over/under-fetching across diverse frontends
- Single endpoint simplifies versioning, reduces endpoint sprawl, and eases maintenance
- Modern tooling addresses caching, auth, and security concerns with fine-grained controls
- Schema introspection provides self-documenting contracts that accelerate development

The Prosecution submits that a conventional REST API is the superior choice for this new public-facing API. Its inherent simplicity, leveraging well-understood HTTP methods and standards, ensures ease of development and maintenance. The built-in HTTP caching capabilities enhance performance and reduce server load without additional complexity. Security is bolstered by established authentication mechanisms, reducing potential vulnerabilities compared to GraphQL's broader attack surface. REST's predictable patterns and modularity facilitate easier onboarding, debugging, and scalability, making it the more maintainable and secure option for this project.
