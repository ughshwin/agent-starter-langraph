Should they start on PostgreSQL (strong consistency, joins, and constraints, but migrations as the schema churns), or a document database (schema-flexible and fast to iterate early, but weaker integrity guarantees and painful once access patterns demand joins and transactions)?

### Opening statements

**DEFENCE — opening statement**

A document database offers unparalleled schema flexibility that is essential when the product’s domain and data structures are still evolving on a weekly basis, allowing developers to iterate quickly without being hindered by rigid schemas or costly migrations; this agility directly translates into higher velocity for delivering new features and responding to user feedback. By embedding related data within nested documents, teams can reduce or eliminate expensive join operations that would otherwise become bottlenecks as the data model changes, while still achieving acceptable performance through intelligent indexing of frequently queried fields. The cost-benefit trade‑off favors document storage in early development because it eliminates downtime associated with migration scripts and reduces operational complexity, enabling the team to focus on value delivery rather than database refactoring. Moreover, modern document engines provide configurable consistency levels, allowing a safe balance between eventual consistency for prototype features and stronger guarantees when needed—thereby preserving data integrity without sacrificing rapid iteration.

_Key points:_
- Schema flexibility eliminates costly migrations during frequent changes.
- Nested documents reduce join overhead and improve write performance.
- Lower operational complexity accelerates feature delivery.
- Configurable consistency models preserve data integrity while enabling agility.


**PROSECUTION — opening statement**

The Prosecution argues that PostgreSQL is the optimal choice for ensuring strong consistency and data integrity from the outset, despite the challenges of schema migrations during model evolution. By enforcing constraints and maintaining strong consistency, PostgreSQL minimizes the risk of data discrepancies, which is crucial for applications requiring accuracy. The robust enforcement of data integrity through constraints reduces reliance on potentially error-prone application-level validation. Furthermore, while migration management presents a short-term challenge, it establishes a scalable foundation that anticipates future growth, thereby mitigating long-term technical debt and ensuring efficient handling of complex queries.

_Key points:_
- Strong consistency ensures up-to-date data across all users and systems.
- Enforcement of constraints reduces data inconsistency risks.
- Prevents reliance on application-level validation for integrity checks.
- Establishes a scalable foundation anticipating future growth.
- Mitigates long-term technical debt and supports efficient complex queries.
